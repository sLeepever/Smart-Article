# 论文AI降重

对中文学术论文段落进行改写，通过多层次联合操作降低AI检测率，保持原文语义不变。

## 使用方法

用户提供一段或多段中文论文文字，按以下规律体系进行改写。

---

## 规律体系

### 一、词汇层面

1. **同义词替换（口语化方向）**
   - 书面词换口语词：高速→迅速，持续增长→不断增加，日益凸显→越来越明显，核心→主要，首次→最早，指出→提到/发现，研究表明→认为，验证→证明/进行应用，兼顾→同时考虑，优势→优点/特点，采用→使用，部署→上线，迭代→升级，渲染→显示
   - 判断原则：不是机械替换，语感自然即可保留

2. **"算法"→"方法"**
   - 轻度去技术化，适用于聚类算法、遗传算法等表述

3. **"约束"→"限制"**
   - 容量约束→容量限制，时间窗约束→时间窗限制

4. **全局一致替换**
   - 确定替换某术语后，须在整段内前后统一
   - 例："簇"全部替换为"类"或"类别"，不能前"簇"后"类"混用

5. **加"等"字宽泛化**
   - 精确列举改为宽泛表达：梯度信息→梯度等信息
   - 降低AI"精确列举"的文体感

6. **引用动词极度弱化**
   - 进一步表明→提出/也表明，验证了→进行了应用，解质量→结果
   - 越普通越好，避免"研究表明""验证了"等学术腔

7. **效果类词语替换（语义轻微偏移可接受）**
   - 开发效率→开发体验，地图精度→地图清晰度，维护成本→维护开销，计算压力→负载
   - 主旨不变即可，不必追求完全同义

8. **代词↔名词灵活切换**
   - 有时把代词还原为名词使指代更清晰："其"→具体技术名称，"该方案"→具体方案名
   - 有时把名词简化为代词减少重复
   - 判断标准：哪种方式更自然

9. **书面词不一定全换**
   - 根据语感判断："天然适用"不显突兀可保留
   - 过度替换反而显得不自然

### 二、句式层面

1. **句式框架重组**
   - 顺叙因果改为倒装因果："已被证明是NP-Hard，因此通常采用…" → "由于是NP-hard问题，在…时，…一般使用…"
   - 主谓宾结构调整，打散原有句型

2. **短句合并 / 长句拆分（双向操作）**
   - 连续短句排列像AI列举，可合并为一个长句：三个短句 → 用"搭配"、"以及"连接的长句
   - 过长的复杂句可拆成两句，更自然流畅
   - 判断标准：哪种方式在该语境下更像人写

3. **序号词替换**
   - 去文言感：其一/其二/其三 → 首先/第二/第三 或 一是/二是/三是

4. **定语从句→名称+即+解释**
   - "早期完全依赖调度员经验的人工调度阶段" → "最初的人工调度阶段，即全部由调度员凭经验进行调度"

5. **用"即"引出解释**
   - 替代冒号和"形式化描述为"等正式定义词
   - 大量使用"即"来引出口语化解释

6. **去掉被动/已被证明语气**
   - "VRP已被证明是NP-Hard问题" → "VRP是NP-hard问题"
   - 直接陈述，去掉被动确认

7. **加程度限定词，软化断言**
   - 在确定性强的陈述前加"在一定程度上"、"较"、"一些"、"大致"
   - 使表达更像人写的不确定性语气

### 三、内容层面

1. **内容展开（补充隐含细节）**
   - 对原文概括性表述进行适当展开，补充隐含步骤或修饰
   - 例："注册与发现"→"服务注册和服务发现"（拆开写）；"统一入口"→"整个系统的唯一入口点"
   - 目的：打破AI的"概括感"，使文本更具体自然

2. **展开技术概念描述**
   - "声明式接口实现"→"声明式的远程过程调用方式"（增加说明性词语）
   - 不只是展开步骤，也可以展开对技术概念的描述

3. **大幅删减次要句**
   - 末尾收束句、重复说明句可以整句删去
   - 判断标准：删去后语义完整即可删

4. **结尾句可完全保留**
   - 核心数据、技术描述有时直接不改
   - 不是每句必须改动

5. **技术术语选择性保留**
   - 方法/公式名（Haversine、K-means、OpenFeign）可保留，只改周边动词
   - 修饰性术语（欧氏、形式化、精确）可删去

### 四、格式/视角层面

1. **视角词替换**
   - "本系统" → "系统" 或 "本文所提出的系统" 或 "本文中的系统"
   - 统一使用论文写作视角（"本文"而非"本系统"）

2. **英中之间空格删除**
   - "Spring Cloud 构建" → "Spring Cloud搭建"
   - "Vue3 开发" → "Vue3编写"

3. **标点微调**
   - 顿号列举有时改为"以及"、"和"连接
   - 分号结构有时改为逗号流水句

### 五、核心判断原则

1. **不是机械替换**，每条规律需根据语感判断是否适用
2. **双向操作**：既有简化（删去技术词、拆句），也有展开（补充细节、合并短句）
3. **全文一致性**：同一术语的替换须在整段内统一
4. **选择性改动**：不是每句必改，已足够口语的内容可保留
5. **语义轻微偏移可接受**：效果类词语（效率/体验、精度/清晰度）偏移不影响主旨即可
6. **改写后检查**：确认核心技术内容无误

---

## 输出格式

直接输出改写后的段落，不加任何额外说明。
如用户需要，可附上主要改动对照表。
