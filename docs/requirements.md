# Smart Article - 智能论文写作 Agent 需求文档

## 1. 项目概述

### 1.1 项目名称
Smart Article

### 1.2 项目定位
基于 LangChain 框架的多 Agent 协作论文写作系统，面向本科生用户，通过纯对话式交互辅助完成中文毕业论文和课程论文的全流程写作，包括选题分析、文献检索、大纲生成、逐章节撰写、降 AIGC 率处理，最终输出 Word 文档。

### 1.3 目标用户
- 本科生
- 需要撰写毕业论文或课程论文
- 论文语言：中文
- 典型场景：用户已完成实验/设计，需要辅助撰写论文；或用户尚未选题，需要从头引导

### 1.4 技术栈
- **运行时**：Bun + TypeScript
- **Agent 框架**：LangChain.js
- **前端**：Next.js（React）
- **数据库**：SQLite（bun:sqlite）
- **认证**：用户登录/注册系统
- **LLM**：多供应商支持（用户自行配置）

### 2.2 Agent 职责定义

#### 2.2.1 Orchestrator Agent（主控 Agent）
- **角色**：用户唯一的对话入口，流程总调度
- **职责**：
  - 与用户进行自然语言对话
  - 判断用户当前阶段（未选题 / 已选题未检索 / 已有实验数据等）
  - 通过对话收集必要信息（专业、主题、实验步骤、设计方案等）
  - 将任务分配给对应的子 Agent
  - 汇总子 Agent 的输出结果，以对话形式呈现给用户
  - 在子 Agent 执行期间，向用户发送状态提示（如"正在检索文献中..."）
  - 根据用户反馈决定是否需要子 Agent 重新执行
  - 管理论文项目的整体状态和进度

#### 2.2.2 Literature Agent（文献检索 Agent）
- **角色**：文献检索与验证专家
- **职责**：
  - 根据选题生成检索关键词（中英文）
  - 调用 Semantic Scholar API 检索文献
  - 调用 CrossRef API 补充和交叉验证
  - 验证文献真实性（DOI/URL HTTP 验证）
  - 筛选和排序文献（按相关性、引用量、年份）
  - 输出结构化文献列表（标题、作者、年份、期刊、摘要、链接）
- **工具**：Semantic Scholar API、CrossRef API、HTTP 验证工具
- **文献数量**：毕业论文 15-30 篇，课程论文 8-15 篇

#### 2.2.3 Writing Agent（写作 Agent）
- **角色**：论文内容生成专家
- **职责**：
  - 生成论文大纲（基于选题 + 文献 + 用户提供的实验/设计信息）
  - 逐章节撰写论文内容
  - 合理引用文献（GB/T 7714 格式）
  - 根据用户反馈修改特定章节
  - 整合全文
- **上下文依赖**：需要接收 Literature Agent 的文献列表、用户的实验步骤/设计方案
- **论文标准结构**：
  - 摘要 + 关键词
  - 第一章 绪论（研究背景、研究意义、国内外研究现状、研究内容与方法）
  - 第二章 相关理论与技术（根据主题动态生成）
  - 第三章-第N章 主体内容（根据主题和用户实验/设计动态生成）
  - 结论与展望
  - 参考文献
  - 致谢

#### 2.2.4 Review Agent（审校 Agent）
- **角色**：论文质量审查专家
- **职责**：
  - 检查章节间逻辑连贯性
  - 检查引用文献的一致性（引用编号与参考文献列表对应）
  - 检查格式统一性
  - 检查语言表达（语病、重复、过度学术腔）
  - 输出审校报告和修改建议

#### 2.2.5 AIGC Reduction Agent（降 AIGC 率 Agent）
- **角色**：AIGC 检测规避专家
- **职责**：
  - 将论文按段落拆分
  - 逐段进行降 AIGC 率改写
  - 遵循改写规律体系（词汇层面、句式层面、内容层面、格式视角层面）
  - 保持原文语义不变
  - 输出改写前后对比
- **改写规律体系**（来源于 `reduce-article-ai/SKILL.md`）：
  - **词汇层面**：同义词替换（口语化方向）、术语弱化、加"等"字宽泛化、引用动词弱化、代词/名词灵活切换
  - **句式层面**：句式框架重组、短句合并/长句拆分、序号词替换、定语从句转换、去被动语气、加程度限定词
  - **内容层面**：补充隐含细节、展开技术概念、删减次要句、技术术语选择性保留
  - **格式视角层面**：视角词替换、英中空格处理、标点微调
  - **核心原则**：非机械替换、双向操作、全文一致性、选择性改动、语义轻微偏移可接受
- **目标检测平台**：知网/万方 AIGC 检测

### 2.3 Agent 间通信

```
用户消息 → Orchestrator Agent
                │
                ├─→ Literature Agent ─→ 文献列表 ─→ Orchestrator
                ├─→ Writing Agent ─→ 章节内容 ─→ Orchestrator
                ├─→ Review Agent ─→ 审校报告 ─→ Orchestrator
                └─→ AIGC Reduction Agent ─→ 改写内容 ─→ Orchestrator
                                                          │
                                              汇总结果 → 用户
```

- Orchestrator 作为唯一的消息中枢，子 Agent 不直接与用户交互
- 子 Agent 之间不直接通信，通过 Orchestrator 传递上下文
- 子 Agent 执行时，Orchestrator 向前端推送状态消息（"正在xxx中..."）

## 3. 核心功能

### 3.1 用户认证
- 登录 / 注册功能
- 基于 JWT 的会话管理
- 每个用户独立的 LLM 配置和论文项目

### 3.2 LLM 供应商配置
用户在 Web 界面上自行配置 LLM 连接信息，支持以下四种 API 格式：

| 格式 | 说明 |
|------|------|
| OpenAI Chat | OpenAI Chat Completions API 兼容格式 |
| OpenAI Response | OpenAI Responses API 格式 |
| Claude | Anthropic Claude API 格式 |
| Gemini | Google Gemini API 格式 |

每种格式需填写：
- **Base URL**（API 端点地址）
- **API Key**
- **模型名称**（如 gpt-4o、claude-sonnet-4-20250514、gemini-2.0-flash）

通过 LangChain 的 provider 抽象层统一调用。

### 3.3 对话式论文写作流程

整个流程通过自然对话驱动，Orchestrator Agent 根据上下文自动判断当前阶段并引导用户。

#### 场景 A：用户从零开始（未选题）
```
用户: 我是计算机专业的，想写毕业论文，方向是深度学习
Agent: [引导选题] → 提供3-5个选题建议
用户: 我选第2个
Agent: [正在检索文献中...] → 展示文献列表
用户: 可以，继续
Agent: [正在生成大纲...] → 展示大纲
...逐步推进
```

#### 场景 B：用户已有实验/设计（需要辅助撰写）
```
用户: 我做了一个基于Vue3的物流管理系统，需要写毕业论文
Agent: 好的，请告诉我你的系统主要功能模块有哪些？
用户: 有用户管理、订单管理、路线规划、数据统计四个模块
Agent: 使用了哪些核心技术？数据库用的什么？
用户: Vue3 + Spring Boot + MySQL，路线规划用了高德地图API
Agent: [正在检索相关文献...] → 展示文献
用户: 可以
Agent: [正在生成大纲...] → 基于用户实验信息生成定制化大纲
...逐步推进
```

#### 流程阶段
无论哪种场景，完整流程包含以下阶段（Orchestrator 自动判断从哪个阶段开始）：

1. **信息收集**：通过对话获取专业、主题、论文类型、实验/设计详情
2. **选题确认**：如用户已有明确选题则跳过，否则提供建议
3. **文献检索**：Literature Agent 执行，结果在对话中展示
4. **大纲生成**：Writing Agent 执行，用户确认后继续
5. **逐章节撰写**：Writing Agent 逐章生成，每章用户确认
6. **全文审校**：Review Agent 检查，展示问题和修改建议
7. **降 AIGC 率**：AIGC Reduction Agent 逐段改写，展示前后对比
8. **导出 Word**：生成 .docx 文件供用户下载

每一步用户都可以：
- 确认并继续下一步
- 要求修改当前步骤的输出
- 补充更多信息
- 回退到之前的步骤

### 3.4 文献检索

#### 数据源
1. **Semantic Scholar API**（主要来源）
   - 端点：`https://api.semanticscholar.org/graph/v1/paper/search`
   - 免费，无需 API Key（有速率限制：100 次/5分钟）
   - 支持中文论文检索
   - 返回字段：标题、摘要、作者、年份、DOI、引用量等
2. **CrossRef API**（补充 + 验证）
   - 端点：`https://api.crossref.org/works`
   - 免费开放
   - 通过 DOI 获取文献元数据
   - 用于交叉验证文献真实性

#### 真实性验证策略
- API 直接返回的文献天然真实
- 对所有文献进行 DOI 链接验证（HTTP HEAD 请求，检查响应状态）
- 非 200 响应的文献丢弃并触发补充检索
- LLM 不参与文献推荐，仅负责生成检索关键词和筛选排序

#### 输出格式（每篇文献）
- 标题（中/英文）
- 作者
- 发表年份
- 期刊/会议名称
- 摘要
- DOI 链接或原始 URL

### 3.5 Word 文档导出
- 使用 `docx` 库（npm: docx）生成 .docx 文件
- 包含：标题层级、正文段落、参考文献列表（GB/T 7714 格式）
- 不做复杂排版，由用户自行调整

## 5. 技术实现细节

### 5.1 LLM 多供应商支持
通过 LangChain.js 的以下 provider 实现：
- `@langchain/openai` — OpenAI Chat Completions + Responses API
- `@langchain/anthropic` — Claude API
- `@langchain/google-genai` — Gemini API

用户配置存储在数据库中（API Key 加密），运行时根据配置动态实例化对应的 LLM provider。所有 Agent 共享同一个 LLM 实例。

### 5.2 降 AIGC 率集成方案
该 skill 本质是一套 **System Prompt 规律体系**（纯文本规则，无可执行代码），集成方式：
- 将 `reduce-article-ai/SKILL.md` 中的改写规律体系作为 AIGC Reduction Agent 的 System Prompt
- Agent 接收一段论文文本，按照规律体系进行改写，直接输出改写后的段落
- 封装为 LangChain 的 Agent，由 Orchestrator 调用

### 5.3 持久化存储
使用 SQLite（bun:sqlite），存储：
- **用户表**：账号、密码哈希、创建时间
- **LLM 配置表**：用户 ID、供应商类型、Base URL、加密 API Key、模型名称
- **论文项目表**：用户 ID、项目名称、当前阶段、创建时间
- **对话记录表**：项目 ID、消息角色（user/assistant/status）、消息内容、时间戳
- **文献缓存表**：项目 ID、文献数据（JSON）
- **论文内容表**：项目 ID、章节结构、各章节内容、大纲

支持用户中断后恢复写作进度（基于对话记录和论文内容重建上下文）。

### 5.4 流式输出
- 前后端通过 WebSocket 连接
- Agent 生成内容时实时流式推送到前端
- 状态消息（"正在xxx中..."）通过独立的消息类型推送

## 6. 非功能需求

### 6.1 性能
- 文献检索结果缓存，避免重复请求
- LLM 调用支持流式输出
- Semantic Scholar API 速率控制（100 次/5分钟）

### 6.2 安全
- 用户密码 bcrypt 哈希存储
- API Key AES 加密存储
- JWT 令牌认证
- 本地部署，数据不上传云端

### 6.3 可扩展性
- 多 Agent 架构天然支持新增 Agent（如翻译 Agent、查重 Agent）
- 文献数据源支持插件化扩展（后续可接入更多数据库）
- LLM Provider 通过 LangChain 抽象层扩展
